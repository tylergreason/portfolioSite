Here is a quick summary of who I am and why you might want to work with me:

- I take coding best practices seriously. In the world of TypeScript, where I spend most of my time, that means (in no particular order):
  - always including access modifiers and return types
  - never using the type "any" and always striving to have types for all variables
  - consolidating repeat code into methods
  - keeping methods below 50 lines
  - not using abbreviations in my code
  - not including useless chaff in my code
  - not including comments in my code (with rare exceptions)
  - never including console logs in my code in frontend applications
  - naming variables after the types they are (IE `thing: Thing;` and `things: Thing[]`)
- I apply all the principles above to all my code reviews. Sometimes this means a lot of back and forth as I help a developer work their code to become more understandable and future-proof.
